# UC-04 出库核验与代取授权

- **负责成员**：成员 D
- **参与者**：学生 / 代取人、驿站工作人员（主参与者）、驿站系统
- **对应目录**：`app/routers/uc04_checkout.py`、`app/db.py`（`authorizations` / `exceptions` 表）、`docs/usecases/UC-04.md`、`frontend/` 工作人员端「出库核验」、`tests/test_api.py` 中 `test_uc04_*`
- **对应 API**：
  - `POST /api/packages/authorize` 生成代取授权码
  - `GET /api/packages/authorize/{code}` 查询授权状态（`{code}` 为取件码）
  - `POST /api/packages/checkout` 出库核验 / 异常件登记
  - `GET /api/packages/exceptions` 异常件清单
- **前置条件**：包裹处于 `in_stock` 状态
- **后置条件**：`picked_up`（已出库）或 `exception`（异常件）；授权记录被标记 `used`

## 基本流

### B1 本人取件出库

1. 工作人员输入取件码，点击「出库核验」。
2. 系统查询包裹，校验 `status = 'in_stock'`。
3. 更新为 `picked_up` 并写入 `picked_up_at`。
4. 返回 `checked_out=true`、出库时间、包裹状态。

### B2 代取授权 + 代取出库

1. 学生在学生端填写取件码、代取人姓名/电话、有效分钟数，调用 `POST /api/packages/authorize`。
2. 系统校验取件码存在且在库，且该取件码没有尚未过期的有效授权。
3. 生成 6 位数字授权码，写入 `authorizations` 表（`expires_at = now + ttl_minutes`）。
4. 学生/工作人员可用 `GET /api/packages/authorize/{取件码}` 查询授权状态（含 `expired` / `used` / `valid`）。
5. 代取人出示取件码 + 授权码，工作人员调用 `POST /api/packages/checkout`。
6. 系统校验授权码存在、与取件码匹配、未使用、未过期，通过后出库并把授权标记 `used=1`。
7. 返回 `auth_code_used` 与「代取出库核验通过」。

### B3 异常件登记

1. 工作人员发现包裹破损/信息不符，输入原因并点击「登记异常件」。
2. `POST /api/packages/checkout` 携带 `report_exception=true`。
3. 系统写入 `exceptions` 表，把包裹状态置为 `exception`，**不出库**。
4. 可通过 `GET /api/packages/exceptions` 查看清单。

## 异常流

| 编号 | 触发条件 | 系统响应 | HTTP |
| --- | --- | --- | --- |
| E1 | 取件码不存在（出库 / 授权 / 查询授权） | `detail: 取件码不存在: ...` | 404 |
| E2 | 重复出库（包裹已是 `picked_up` / `exception`） | `detail: 重复出库或包裹不可出库...` | 409 |
| E3 | 代取授权码错误或与该取件码不匹配 | `detail: 代取授权码无效或与取件码不匹配` | 403 |
| E4 | 代取授权已过期（`ttl_minutes <= 0` 或超时） | `detail: 代取授权已过期，请重新授权` | 403 |
| E5 | 代取授权码重复使用 | `detail: 代取授权码已使用` | 409 |
| E6 | 同一取件码重复申请有效授权 | `detail: 该取件码已有有效授权，请勿重复授权` | 409 |
| E7 | 对已出库 / 异常包裹申请授权 | `detail: 包裹不在库，无法授权...` | 409 |
| E8 | 查询一个从未授权的取件码 | 正常返回 `valid=false`、`reason=从未授权` | 200 |

## 验收要点

- 过期判定统一走 `_auth_status()`：`now >= expires_at` 即过期；用 `ttl_minutes=0` 即可在测试中稳定构造过期场景，无需 mock 系统时间。
- 授权码 `UNIQUE`，生成时循环避让冲突。
- 异常件登记与正常出库互斥：`report_exception=true` 优先于出库校验。
- 上述 E1~E8 全部有对应单元测试；smoke 脚本也逐一打印了真实响应。
