# UC-01 取件码解析与包裹聚合查询

- **负责成员**：成员 A（纵向分工：用例文档 → 后端路由 → 前端模块 → 测试）
- **参与者**：学生（主参与者）、驿站系统
- **对应目录**：`app/routers/uc01_lookup.py`、`app/codes.py`、`docs/usecases/UC-01.md`、`frontend/` 学生端「取件码查询」、`tests/test_api.py` 中 `test_uc01_*`
- **对应 API**：`GET / POST /api/packages/lookup?code=<取件码>`
- **前置条件**：数据库已建表并写入演示包裹数据（seed 中学生「张三」有 3 个包裹）
- **后置条件**：不改变任何包裹状态（只读用例）

## 基本流

1. 学生在学生端输入取件码（或由扫码得到，例如 `A-1-01-001`），点击「查询」。
2. 前端以 Fetch 调用 `GET /api/packages/lookup?code=A-1-01-001`。
3. 系统用正则 `^([A-F])-([1-5])-(\d{2})-(\d{3,6})$` 校验取件码格式。
4. 系统解析出货架号：区 `A`、层 `1`、格 `01`，即「A区-1层-01格」。
5. 系统按完整取件码查询 `packages` 表，定位到该包裹记录。
6. 系统取出该记录的 `student_id`，再查询**该学生名下所有包裹**（不局限于当前取件码）。
7. 返回 JSON：`code`、解析出的 `shelf`、`student`、聚合总数 `total` 与 `packages` 列表。
8. 前端渲染货架号、学生姓名、包裹总数及包裹表格（运单号 / 取件码 / 货架位 / 尺寸 / 状态）。

> 演示结果：取件码 `A-1-01-001` → 学生张三，`total = 3`，返回 `A-1-01-001`、`A-1-02-002`、`A-1-03-003` 三个包裹。

## 异常流

| 编号 | 触发条件 | 系统响应 | HTTP |
| --- | --- | --- | --- |
| E1 | 取件码格式非法（如 `bad-code`、`A-1-1-1`、空串） | `detail: 取件码格式非法...正确格式如 A-1-01-001` | 400 |
| E2 | 格式合法但库中不存在（如 `F-5-20-999`） | `detail: 取件码不存在: ...` | 404 |
| E3 | 请求未带 `code` 查询参数 | FastAPI 参数校验失败 | 422 |
| E4 | 同一学生名下部分包裹已出库 / 异常 | 仍完整返回，列表中 `status` 分别显示 `picked_up` / `exception`（前端显示徽标） | 200 |

## 验收要点

- GET 与 POST 两种方式均可查询（需求写明 `POST/GET`）。
- 聚合以 `student_id` 为键，而非只返回单个取件码对应包裹。
- 解析出的货架号与 `packages` 表存储的 `area/level/slot` 一致（入库按同一规则生成）。
- 异常分支 E1/E2/E3 均有单元测试覆盖。
