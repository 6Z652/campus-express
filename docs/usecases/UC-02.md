# UC-02 高峰期排队预测与错峰提醒

- **负责成员**：成员 B
- **参与者**：学生（主参与者）、驿站系统
- **对应目录**：`app/forecast.py`、`app/routers/uc02_forecast.py`、`tests/test_forecast.py`、`docs/usecases/UC-02.md`、`frontend/` 学生端「排队预测与错峰建议」
- **对应 API**：`GET /api/queue/forecast`
- **前置条件**：`queue_history` 表已有历史时段平均取件时长（seed 提供 8~20 点共 13 个时段）
- **后置条件**：只读用例，不修改数据

## 基本流

1. 学生进入学生端（或点击「刷新预测」）。
2. 前端调用 `GET /api/queue/forecast`。
3. 系统统计当前待取件数：`SELECT COUNT(*) FROM packages WHERE status='in_stock'`，作为排队人数近似值。
4. 系统读取 `queue_history` 得到 `{hour: avg_service_minutes}`，并取当前小时。
5. 系统按 `app/forecast.py` 的确定性公式计算：

   ```
   avg  = 当前时段历史均值
          无该时段数据，或该时段值为 NULL -> 全部有效历史时段的算术平均
          完全无可用历史数据 -> 默认 1.5 分钟
   wait = ceil(pending_count * avg / servers)     # servers 默认 2
   level: wait<=2 空闲 / <=5 正常 / <=10 繁忙 / >10 高峰
   推荐错峰时段 = 历史中平均服务时长最低的非当前时段；无历史则给 10:00 或 15:00
   ```

6. 返回 `current_hour / pending_count / servers / avg_service_minutes / predicted_wait_minutes / congestion_level / recommended_offpeak_hour / recommendation / algorithm`。
7. 前端以中文表格展示预计等待分钟数、拥挤等级、推荐错峰时段与算法说明。

> 算法取舍：课程项目不引入排队论仿真，采用可解释、可复现的确定性「工作量 / 并行窗口数」模型，保证同一输入必然得到同一输出，便于断言与 CI。

## 异常流 / 边界流

| 编号 | 触发条件 | 系统响应 | 覆盖位置 |
| --- | --- | --- | --- |
| E1 | 待取件数为 0（无人排队） | `predicted_wait_minutes = 0`，`congestion_level = 空闲` | `test_zero_queue_returns_zero_wait` |
| E2 | 待取件数为负（异常入参） | 按 0 处理，返回 0 | `test_negative_queue_is_treated_as_zero` |
| E3 | 高峰时段（12 点，历史 3.2 分钟，20 人排队） | `wait = ceil(20*3.2/2) = 32`，等级「高峰」 | `test_peak_hour_prediction` |
| E4 | 完全无历史数据（`{}` 或 `None`） | 回退默认 1.5 分钟，推荐经验错峰时段 | `test_no_history_uses_default_service`、`test_none_history_uses_default_service` |
| E5 | 当前时段无历史记录 | 回退到全局历史均值 | `test_average_service_missing_hour_falls_back_to_global_mean` |
| E6 | `servers <= 0` 或 `avg <= 0` | `servers` 兜底为 1；`avg<=0` 返回 0 分钟 | `test_zero_servers_is_guarded`、`test_zero_service_minutes_returns_zero` |
| E7 | 推荐时段与当前时段相同 | 自动跳过当前时段，选次优时段 | `test_recommend_offpeak_picks_lowest_non_current_hour` |
| E8 | 历史表中当前时段值为 NULL（采集缺失） | 按「无该时段数据」回退到全部有效历史时段的算术平均，不得抛异常 | `test_history_hour_value_none_falls_back_to_global_mean` |
| E9 | 待取件数 ≥ 1 但工作量不足 1 分钟 | 向上取整为 1 分钟，不得显示 0 分钟 | `test_nonzero_queue_never_reports_zero_wait` |

## 验收要点

- 算法全部为纯函数，不依赖数据库与网络，可独立单元测试；`tests/test_forecast.py` 共 15 个用例全部通过。
- `predicted_wait_minutes` 随 `pending_count` 单调不减（`test_peak_prediction_is_monotonic_with_queue`）。
- 相同输入重复调用结果完全一致（`test_forecast_is_deterministic`）。
- `avg_service_minutes` 的取值顺序为「当前时段 → 全部有效历史均值 → 1.5 分钟兜底」，NULL 值在取值前先剔除（E5、E8）。
- 只要 `pending_count >= 1`，`predicted_wait_minutes >= 1`（E9，由 `ceil` 保证）。
- API 响应中显式携带 `algorithm` 字段，便于报告说明可解释性。
