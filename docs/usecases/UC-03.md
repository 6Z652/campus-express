# UC-03 入库与货架分配

- **负责成员**：李艳慧
- **参与者**：驿站工作人员（主参与者）、驿站系统
- **对应目录**：`app/routers/uc03_checkin.py`、`app/db.py`（`packages` 表与 seed）、`app/codes.py`（货架位分配）、`docs/usecases/UC-03.md`、`frontend/` 工作人员端「入库与货架分配」、`tests/test_api.py` 中 `test_uc03_*`
- **对应 API**：`POST /api/packages/checkin`
- **前置条件**：工作人员已登录工作台（本骨架不实现鉴权，仅记录 `operator` 概念），数据库已建表
- **后置条件**：新增一条 `in_stock` 包裹记录，生成取件码并分配货架位

## 基本流

1. 工作人员扫描运单号并填写学号、姓名、电话、尺寸，点击「扫码入库」。
2. 前端调用 `POST /api/packages/checkin`，请求体为 `CheckinRequest`。
3. 系统先按 `tracking_no` 查询 `packages` 表，判断是否已入库。
4. 若为新运单，取 `MAX(id)+1` 作为入库序号 `index`。
5. 调用 `shelf_position(index)` 确定性分配货架位：

   ```
   区   = A~F，每 100 个格换一区（循环）
   层   = (index-1)//20 % 5 + 1        （每区 5 层）
   格   = (index-1) % 20 + 1           （每层 20 格，两位补零）
   标签 = 例如 A区-1层-06格
   ```

6. 调用 `make_pickup_code(index, pos)` 生成取件码：`A-1-06-006`（序号取主键，保证唯一）。
7. 写入 `packages` 表，`status = 'in_stock'`，记录 `created_at`。
8. 返回 `created / idempotent / message / pickup_code / shelf / package`。
9. 前端展示取件码与货架位；该包裹可立即被 UC-01 的取件码查询检索到。

## 异常流

| 编号 | 触发条件 | 系统响应 | HTTP |
| --- | --- | --- | --- |
| E1 | 同一 `tracking_no` 重复提交 | 幂等：不重复插入，返回 `created=false, idempotent=true` 与已存在记录 | 200 |
| E2 | 请求体缺少 `tracking_no` / `student_id` / `student_name` 等必填字段 | Pydantic 校验失败 | 422 |
| E3 | 货架容量用尽（6 区 × 5 层 × 20 格 = 600 个格位后） | 按规则循环复用货架区，取件码序号仍取主键保证唯一（非错误，业务上需人工理架） | 200 |
| E4 | `tracking_no` 与已有记录相同但其他字段不同 | 以首次入库信息为准，不覆盖（幂等语义） | 200 |

## 验收要点

- 幂等性由数据库 `tracking_no UNIQUE` + 前置查询双重保证；测试断言重复提交后表中仍只有 1 条记录。
- 取件码格式与 UC-01 的解析正则完全一致，保证「入库生成 → 查询解析」闭环。
- 货架位分配为确定性函数，测试可断言第 6 个入库包裹得到 `A-1-06-006`。
- 入库结果可立即被 UC-01 查询到（跨用例集成验证）。
- 幂等重复提交时以首次入库信息为准，其他字段（如姓名）不被覆盖（`test_uc03_idempotent_keeps_first_record`，同时断言库中仍为 6 条记录）。
- 连续入库两件时入库序号与货架位依次递增：序号 6/7 → `A-1-06-006`、`A-1-07-007`（`test_uc03_sequential_checkin_increments_shelf`）。
